# Build home.microprediction.org

An academic publications page generated from data. Organized by **research theme**
(related work sits together); within each theme, published work / preprints come
first, then the most recent working drafts. Restrained academic styling — serif,
low bold, abstracts in collapsed `<details>`.

## Files

| File | Role |
|------|------|
| `papers.json` (repo root) | **Source of truth.** `site`, `book_length[]`, `themes[]` (each with `papers[]`), `software[]`, `talks[]`, `patents[]`, `more[]`. **Edit this.** |
| `abstracts.json` (repo root) | Generated cache of **real** abstracts keyed by title. Committed so CI needn't extract. |
| `scan.py` | Read-only. Scans `../{schur,humpday,precise,mechanics,skaters,inventory}` for draft PDFs/TeX + arXiv ids. |
| `status.py` | Read-only. Posting status of every paper: SSRN and arXiv ids from the links, latest arXiv version and date from the API, SSRN dates from `posted.json`, and the last commit date of the local draft (resolved through the sibling repos' CNAME files). Writes `STATUS.md` and `status.json` at the root. |
| `posted.json` (repo root) | Hand-kept SSRN register keyed by abstract id: `posted` and optional `revised` dates. Add a line whenever a paper is uploaded or revised on SSRN; nothing can scrape it. |
| `STATUS.md` (repo root) | Generated by `status.py`: one row per visible paper with local date, SSRN, arXiv and a status (published, in sync, local newer (N days), not posted, unknown SSRN date, unresolved local). Commit it with the run. |
| `extract_abstracts.py` | Local only (needs pdftotext + sibling repos). Pulls real abstracts → `abstracts.json`. |
| `build.py` | Renders `papers.json` + `abstracts.json` → `docs/index.html`, `docs/academic.css`, `docs/CNAME`. Pure stdlib; runs in CI. |

## Paper entry

```json
{ "title": "...", "venue": "SIAM J. Financial Math., 2021",
  "draft_new": true, "abstract_source": "https://github.com/.../x.tex",
  "links": [ {"label":"arXiv","url":"..."}, {"label":"latest draft","url":"..."} ] }
```
- `venue` present ⇒ published (rendered italic); put the year in it.
- `date` (`"2026-09"` or `"2022"`) is required on every working paper and is rendered
  at the start of the links row. Take it from the draft's title page, else git history. List the canonical link (`arXiv`/`journal`) **first**.
- `latest draft` label is highlighted; use a **PDF** url, never a raw `.tex`.
- `draft_in_progress: true` shows a muted "draft in progress" note (no link).
- `note: true` marks a **technical note** rather than a paper: rendered with a
  small "technical note" tag and hidden when the reader unticks the
  "include technical notes" checkbox (ticked by default). Peter decides which
  entries are notes; default is paper.
- `hidden: true` keeps the entry in `papers.json` but leaves it off the page
  (Peter's call: premature or trivial drafts). Never delete an entry to hide it;
  set the flag so the census stays complete. A theme with nothing visible is skipped.
- Every working paper needs a **PDF** link (`latest draft` or `pdf`). If the only
  copy is TeX, compile it and publish the PDF to the package site's `docs/` first.
- `abstract_source` = a local file to extract the abstract from when it isn't one of the entry's links (e.g. a TeX with no public PDF).

## ULTRA reading list

The optional top-level `ultra` object adds a collapsed editorial foldout
beside `highlight` (Peter's "My personal favourites"). It renders as one
ranked list: rank, linked title, and a one-sentence `verdict` per paper, with
any longer assessment folded under "more". Keep the assessment in
`papers.json`, separate from the verbatim abstracts:

```json
{
  "ultra": {
    "summary": "what ULTRA thinks",
    "reviewed": "2026-10-31",
    "description": "Two sentences at most.",
    "note": "Who wrote which ranks, shown in the meta line when any entry has 'by'.",
    "entries": [
      { "title": "Exact title from a visible theme paper or book_length",
        "verdict": "One sentence for an outside reader: what the paper removes and why it matters.",
        "why": "Optional short case; folds under 'more'.",
        "caveat": "Optional scope limits; folds under 'more'.",
        "heritage": "Optional earlier work it builds on; folds under 'more'.",
        "by": "Claude  (only on entries not written by ULTRA)" }
    ]
  }
}
```

Entry order sets rank; there is one list, never a second tier. `verdict` is
required. Entries with `by` were added by someone other than ULTRA and the
build then requires `note` to say so. The generator resolves links from the
catalogue (journal, arXiv, SSRN, DOI, MIT Press, then latest draft or PDF);
do not duplicate URLs here. Unknown, ambiguous, duplicate or hidden titles
fail the build. Omitting `ultra` omits the foldout.

## Procedure

0. **Posting status** — `python3 status.py` (or `--offline`). Read `STATUS.md`: "local newer" rows are drafts that have moved since they were posted and may need a revision upload; "unknown SSRN date" rows need a line in `posted.json`; "unresolved local" rows have a draft link the script cannot map to a sibling repo.
1. **Find what's new / verify arXiv ids** — `python3 scan.py`. To confirm an
   arXiv id belongs to Peter (vs. someone citing him), check the author:
   `curl -s "https://export.arxiv.org/api/query?search_query=au:%22Peter+Cotton%22&max_results=40"`.
2. **Edit `papers.json`** — add/move papers into the right theme, published-first;
   add arXiv/journal/draft links. Don't invent abstracts or arXiv pairings.
3. **Abstracts** — `python3 extract_abstracts.py` (local). It writes only abstracts
   it can extract verbatim; papers without a clean source get none (that's fine —
   never fabricate). To add a missing one, paste the real text into `abstracts.json`.
4. **Build** — `python3 build.py`. Then `open docs/index.html` to review.
5. **Publish** — commit `papers.json`, `abstracts.json` and the skill. The Pages
   workflow runs `build.py` and deploys `docs/`. DNS already points
   `home.microprediction.org` → `microprediction.github.io`.
